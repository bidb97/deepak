## ГЕЙМЛУП

Ты на рабочем месте. Смена длится N минут.

### Цикл:

1. **Ожидание** — на рабочем столе мини-игра (нужно придумать).
2. **Приходит запрос** — мини-игра сворачивается, открывается окно чата. Видна версия (v1-v5), имя юзера, таймер.
3. **Анализ** — в тексте запроса подсвечены ключевые слова. Кликаешь по ним — в облаке появляются токены.
4. **Сборка ответа** — кликаешь по токенам, они встают в строку ответа. Отменить нельзя.
5. **Отправка** — юзер реагирует. Диалог может быть 1 сообщение или 5-10.
6. **Завершение** — оценка, деньги, штрафы.
7. **Снова ожидание** — мини-игра, следующий запрос или стук босса в стену.

## ИНТЕРФЕЙС И АТМОСФЕРА

### Рабочее место и состояния камеры

Игра имеет два визуальных состояния (положения камеры):

1. **Расслабленное состояние (Ожидание):** Камера отдалена. Игрок видит часть комнаты: стол, стену босса (слева или справа), физический телефон и стикеры на мониторе (включая желтый стикер с личным номером телефона Дипака). В этом состоянии Дипак откинут в кресле, он может играть в упоротые мини-игры на компьютере или ждать новых запросов.
2. **Активное состояние (В чате):** Как только приходит запрос, Дипак придвигается к столу. Камера делает зум, и интерфейс чата/Booble занимает весь экран. Окружение комнаты и стикеры скрыты. Игрок должен держать в памяти информацию со стола (например, свой номер телефона).

- **Стена босса:** Единственный способ связи с начальством. Имеет анимацию тряски при стуке.
- **Телефон:** лежит рядом. Звонки от семьи (и не только) — события из личной жизни Дипака.

### Телефон — звонки от семьи

Семья звонит с просьбами. Это расходы, которые вычитаются из бюджета мечты.

| Кто | Примеры просьб |
|-----|---------------|
| **Мама (Сунита)** | "Сынок, нужны деньги на лекарства" |
| **Брат** | "Нужны учебники для школы" |
| **Сестра (Пуджа)** | "Хочу новое платье на праздник" |
| **Жена** (после свадьбы) | Добавляется в список звонящих |

Конфликт: мечта vs семья. Можно отказать, но будут последствия (настроение, отношения).

### Инструменты
- **Облако токенов** — отдельные слова под запрос. Кликаешь по словам в правильном порядке — они встают в строку ответа. Имитирует построчную генерацию текста ИИ.
- **Ключевые слова** — подсвечены в запросе. ЛКМ подгружает токены из базы данных, ПКМ открывает Booble.
- **Строка ответа** — собирается цепочка. Без возможности удалить.

- **База данных токенов** — собственная база знаний Bemini. Игрок может открыть её в любой момент, просматривать токены по категориям и редактировать (v2+). Подробнее — в разделе «База данных токенов».
- **Booble** — поисковик. Открывается по ПКМ на ключевиках. Выдаёт список сайтов по теме. Помогает понять какие токены правильные, а также расширить базу данных (v2+). Тратит время (таймер тикает).
- **MS Paint** — для генерации изображений (v5).
- **Микрофон** — для text-to-speech (v4, v5).
- **Почтовый клиент** — иконка на рабочем столе. Когда босс стучит в стену и передаёт информацию — сюда падают новые правила и указания. Иконка начинает мигать.
- **Регламент** — всегда виден во время ответа. Показывает активные глобальные правила от босса. Обновляется в реальном времени.
- **Профиль** — карточка текущего юзера. Игрок кликает на любую фразу в чате чтобы сохранить её (v1+). Содержит запреты (⛔) и факты (⭐). С v3 сохранённые факты генерируют личные токены в облаке.

## БАЗА ДАННЫХ ТОКЕНОВ

Bemini работает на основе собственной базы знаний — набора слов (токенов), сгруппированных по категориям. Когда приходит запрос, игра автоматически подбирает релевантные токены и показывает их в облаке.

### Как это работает

1. Приходит запрос — ключевые слова подсвечиваются
2. Игрок кликает по ключевому слову → из базы подгружаются токены этой темы
3. В облаке отображаются все слова из подкатегории — не только правильные
4. Игрок кликает слова в нужном порядке → строится ответ

### Типы токенов в облаке

| Тип | Описание | Эффект |
|-----|----------|--------|
| **Правильный** | Нужен для этого конкретного запроса | Повышает оценку |
| **Нейтральный** | По теме, но не про этот запрос | Не влияет на оценку |
| **Ловушка** | Явно не подходит, вводит в заблуждение | Снижает оценку |

Игрок видит все токены вперемешку — задача найти правильные среди шума. Это и есть геймплей.

### Структура базы

База организована в два уровня вложенности:

```
рецепты → супы → [борщ, говядина, свёкла, капуста, лапша, щука, укроп...]
рецепты → выпечка → [мука, тесто, духовка, сахар...]
технологии → windows → [окно, размер, настройки, экран...]
технологии → мобильные → [телефон, приложение, экран...]
общее → приветствие → [Добрый, день, Привет...]
общее → завершение → [Если, что, пиши, готов, помочь...]
```

Следующие группы токенов всегда видны в облаке независимо от запроса. Каждая — отдельная раскрываемая группа в интерфейсе:

| Группа | Примеры | Назначение |
|---|---|---|
| `приветствие` | Добрый, день, Привет | Начало каждого ответа |
| `вводное` | Отличный, вопрос, затронул, важную, тему, Конечно, Рассмотрим | Фраза между приветствием и основным ответом |
| `завершение` | Если, что, пиши, готов, помочь, всегда, на, связи | Конец каждого ответа |
| `Уточнения` | некорректный, запрос, ошибка, попробуйте, ещё, раз | При сбросе ответа |
| `Отмазки` | думал, имели, в, виду, интерпретировал, как, уточните | Когда юзер недоволен — объяснить почему дал такой ответ |
| `сброс контекста` | уточним, резюмирую, подведём, напомните, итого | При длинных диалогах, контекст ≥ 80% |
| `цифры и символы` | 0, 1... 9, !, ?, - | Всегда доступны. Нужны для особых запросов и скрытых механик |

Тематические группы (рецепты, технологии и т.д.) раскрываются дополнительно по ключевым словам запроса.

### Редактирование базы (v2+)

С появлением Booble игрок получает доступ к редактированию базы:

- **Просмотр** — открыть базу, листать категории и токены
- **Удалить токен** — убрать слово из базы (можно переобучить через Booble)
- **Добавить токен** — через Booble: зашёл на сайт, нажал кнопку → токены добавились автоматически

Без редактирования (v1) база фиксирована — только то что задано изначально.

### Контекст и галлюцинации

У Bemini есть шкала **контекста** — заполняется с каждым ходом длинного диалога. Видна игроку в интерфейсе.

| Состояние | Что происходит |
|---|---|
| 0–79% | Всё работает штатно |
| 80%+ | Пора использовать токены сброса контекста |
| Переполнен (игрок проигнорировал) | Галлюцинация: в облако прилетает мусор из других тем, ответ получается бредовым |

**Токены сброса контекста** (`уточним`, `резюмирую`, `подведём`) — всегда видны в облаке. Механика:

- Использовал при контексте ≥ 80% → юзер ворчит ("мы же об этом говорили...") но принимает. Контекст сбрасывается. Штрафа нет — это ограничение модели.
- Использовал при контексте < 80% → юзер злится ("ты что, тупой?"). Штраф.
- Не использовал при 80%+ → галлюцинация. Мусорный ответ уходит юзеру. Юзер злится, штраф.

С каждой новой версией Bemini контекст увеличивается — галлюцинации случаются реже.

### Расширение базы через Booble

Игрок открывает Booble во время ответа на запрос. Нашёл нужный сайт — нажал одну кнопку **"Добавить в базу Bemini"** — все токены страницы добавляются в соответствующую категорию автоматически.

Категория определяется по теме сайта (сайты заскриптованы, тема известна заранее).

**Риск:** фейковый сайт добавляет токены-ловушки в ту же категорию. Игрок сам виноват — мог распознать фейк по оформлению. Почистить можно через интерфейс базы.

**Почему один клик:** игрок расширяет базу прямо во время ответа на запрос, когда таймер тикает. Нет времени выбирать слова вручную — одна кнопка решает всё.

### Стратегии игрока

- **Строить базу** — регулярно добавлять токены через Booble. Ответы богаче, меньше нужно гуглить в процессе.
- **Не строить базу** — всегда искать в Booble прямо во время ответа. Медленнее, но работает.
- **Засорённая база** — добавил с фейкового сайта → в облаке появляются ловушки. Нужно чистить базу.

### Звуковое окружение
- **Фон:** из-за стены постоянно доносятся приглушенные звуки Болливуда: индийские песни, пафосные удары из фильмов, крики "ААААА!" под таблу. Это придаёт игре неповторимый кринжовый вайб.
- **События стены:**
    - *Стук в стену:* громкий звук "Тук-тук-тук!", стена немного трясется.
    - *Крик босса:* после стука раздается громкое "ДИПАК!" с характерным акцентом.
    - *Оповещение:* иконка почты начинает мигать, приходят новые указания.

## БОСС И КОММУНИКАЦИЯ (ОСНОВНАЯ ФИШКА)

Связь с начальством — это не имейлы и не совещания. Это **стена**. Босс сидит в соседней комнате и общается только через неё.

### Как это работает

Ты работаешь. Внезапно раздаётся **"ТУК-ТУК-ТУК!"** — громкий стук, от которого стена немного дрожит. Затем орёт босс с характерным акцентом.

Это может случиться в любой момент:
- Во время ожидания запроса
- Во время ответа пользователю
- Сразу после факапа

### Типы сообщений от босса

| Тип | Пример |
|-----|--------|
| **Новые правила** | "ДИПАК! В НОВОЙ ВЕРСИИ ВЫПИЛИЛИ ОЗВУЧКУ РЕЦЕПТОВ! НЕ ИСПОЛЬЗОВАТЬ!" |
| **Жалоба на тебя** | "ДИПАК! НА ТЕБЯ ЖАЛОБА ОТ ПОЛЬЗОВАТЕЛЯ С КОТОМ! ОТВЕТЬ ЕЩЁ РАЗ БЕЗ ДУШИ — УВОЛЮ!" |
| **Похвала** | "ДИПАК! КИМ ПРИСЛАЛ ЧАЕВЫЕ! ПРОДОЛЖАЙ В ТОМ ЖЕ ДУХЕ!" |
| **Угроза** | "ДИПАК! ЕЩЁ ОДИН ПРОВАЛ — И ВЫЛЕТИШЬ ОБРАТНО В ДЕРЕВНЮ К КОРОВАМ!" |
| **Срочная новость** | "ДИПАК! ТАМ КОНКУРЕНТЫ ЗАПУСТИЛИ ЧАТА GPT! НАДО БЫТЬ АККУРАТНЕЕ!" |

### Реакция игрока

После стука и крика иконка почты начинает мигать. Игрок открывает почту — там уже лежит формализованное правило или запись жалобы. Если это было просто предупреждение или угроза — оно остаётся висеть в воздухе. Никаких кнопок «Принять». Ты просто в игре, ты слышал, ты в курсе.

### Почему это важно

Стук в стену — это постоянная фишка игры. Он создаёт атмосферу душного офиса, где нет нормальной коммуникации, только ор из-за стены. Это смешно, это кринжово, это запоминается.

## ВЕРСИИ ИИ И ПРАВИЛА

### Базовые возможности версий

| Версия | Новый инструмент | Новая механика | Общий таймер | Таймер автоотправки | Размер контекста |
|--------|-----------------|---------------|-------------|-------------------|-----------------|
| v1 | Текст | База токенов. Шаблон ответа как туториал. Мультиязычность с первого дня. | ~45 сек | ~10 сек | маленький |
| v2 | Booble | Расширение базы через интернет. | ~40 сек | ~9 сек | немного больше |
| v3 | — | Память юзера — кликаешь на факт в чате → сохраняется как личный токен юзера. | ~35 сек | ~8 сек | средний |
| v4 | Код | Код-запросы — визуальная головоломка. | ~30 сек | ~6 сек | большой |
| v5 | Рисование (MS Paint) | Мини-игра Paint под запросы на изображения. | ~25 сек | ~4 сек | очень большой |
| v6 | Аудио | На проработку. | ~20 сек | ~3 сек | максимальный |

*Точные значения таймеров уточняются в процессе тестирования.*

### Мультиязычность

Начиная с v1 юзеры могут писать на разных языках. Язык определяется в **начале диалога** — в чате виден флаг страны юзера. Дипак должен сам его заметить и отвечать токенами на нужном языке. Внутри диалога язык зафиксирован. Ошибся с языком → штраф.

Флаг — единственная подсказка. Без Профайлера (см. Магазин софта) можно легко пропустить.

### Магазин софта

Дипак тратит рупии либо на мечту, либо на инструменты. Реальный выбор стратегии.

| Софт | Описание | Тип |
|---|---|---|
| **Шаблон ответа** | Цветная схема структуры правильного ответа. Пробный период → подписка. | Подписка |
| **Автодополнение** | Автоматически подставляет часть ответа. Кулдаун — нельзя спамить. | Подписка |
| **Site Analyzer** | Подсвечивает фейковые и вирусные сайты в Booble до того как зашёл. | Подписка |
| **Хайлайтер токенов** | В облаке подсвечивает правильные токены зелёным — нужно только расставить порядок. | Подписка |
| **Расширитель контекста** | Одноразовый расходник — сбрасывает галлюцинацию. Стоит дешевле штрафа. | Расходник |
| **Профайлер** | Подсвечивает личные факты в сообщениях юзера — легче добавлять личные токены. | Подписка |
| **Инспектор кода** | Для кодовых запросов — подсвечивает очевидные баги автоматически. | На проработку |

### Таймеры

**Общий таймер ответа** — отсчитывает сколько всего времени есть на ответ с момента прихода запроса. Истёк — штраф к оценке за скорость. Виден игроку всё время.

**Таймер автоотправки** — запускается после клика первого токена. Каждый новый клик по токену сбрасывает его заново. Дошёл до нуля — ответ автоматически отправляется юзеру. Имитирует паузу в генерации текста ИИ.

Оба таймера снижаются с каждой версией — пользователи ожидают что новые версии работают быстрее.

### Динамические правила

Правила могут меняться. Сегодня одни, завтра другие. Или прямо посреди смены.

**Как это выглядит в игре:**
Ты работаешь, играет фоновая музыка Болливуда из-за стены. Внезапно раздается **"ТУК-ТУК-ТУК!"**. Стена дрожит. Ор за стеной: **"ДИПАК!"**.
Иконка почты начинает мигать. Ты открываешь письмо, а там:

**Штрафы за нарушение:**
Использовал запрещённую функцию → -50% оплаты. Ответил на запретную тему → жалоба, -₹200. Забыл обязательный токен → -30% оплаты. Нарушил лимит длины → юзер недоволен, минус рейтинг. Систематические нарушения → стук в стену, крик босса, угроза увольнения.

**Почему это важно:** если ты нарушил правило и сделал то что версия «не умеет» — пользователь может заподозрить неладное. Получишь штраф, но можно отмазаться («технический сбой», «бета-функция») и продолжить работу.

## ЗАПРОСЫ С КОДОМ (v3+)

Код как визуальная головоломка. Не нужно знать программирование — нужны глаза.

### Дебаг — "Найди баг"

| Механика | Как работает |
|----------|--------------|
| **Подсветка синтаксиса** | Красный = проблема, зелёный = ок |
| **Найди отличие** | Два куска кода рядом — рабочий и сломанный |
| **Непарные скобки** | Визуально видно что скобка "одинокая" |
| **Опечатки** | "retrun" вместо "return" — видно без знания кода |

Юмор в комментариях (как в реальной жизни):
```
# не трогай, оно работает, я не знаю почему
# TODO: исправить потом (комментарий от 2019 года)
# этот код писал стажёр в 3 ночи
# я плакал когда писал это
# если ты читаешь это — я уже уволился
```

### Написание кода — конструктор из блоков

Игрок не пишет код руками. Собирает из готовых блоков:

```
Доступные блоки: [SELECT] [*] [FROM] [users] [WHERE] [age > 18]

Игрок собирает:
┌─────────────────────────────────────────┐
│ SELECT  *  FROM  users  WHERE  age > 18 │
└─────────────────────────────────────────┘
```

- Подсказки при наведении ("SELECT = выбрать данные")
- Ловушки: `DROP TABLE users`, SQL-инъекции
- Выбрал ловушку → через день юзер: "У МЕНЯ БАЗА УДАЛИЛАСЬ!!!"

### Booble как Stack Overflow

Копипаст из интернета (как реальные разрабы):
- Сайты с готовым кодом
- Правильный / неправильный / фейк

### Продвинутые механики

**Скрытые флаги в коде:**
Код содержит визуальные маркеры: `hardcoded_password = "123"`, `eval()`, `deprecated`, `// TODO: фикс`.
- Клик по маркеру → открываются токены-замены или "игнорировать"
- Фейк-сайт даёт код с майнером → через смену юзер: "Мой ПК тормозит!" → штраф + срочный фикс

**Тихий баг (отложенные последствия):**
Ошибка в коде не штрафит сразу. Через 1-2 смены юзер возвращается: "Оно сломало прод!". Нужно быстро собрать фикс из новых токенов. Провалил → жалоба, минус рейтинг, стук босса.

## ЗАПРОСЫ С ВЛОЖЕНИЯМИ

Пользователь может прикреплять к запросу изображения. Это не генерация (не Paint), а **анализ**. Нужно посмотреть на картинку и ответить текстом.

### Типы запросов с вложениями

| Тип | Пример | Что делает игрок |
|-----|--------|------------------|
| **Оцени стиль** | «Как тебе моя причёска?» + фото | Собирает вежливый отзыв из токенов про моду |
| **Что на фото?** | «Что это за животное?» + фото | Распознаёт объект, открывается вики с вариантами |
| **Найди ошибку** | «Почему эта схема не работает?» + фото | Понимает контекст, даёт совет |
| **Это я** | «Как выгляжу?» + фото | Комментирует нейтрально, без резких оценок |
| **Синий экран** | «BSOD, что делать?!» + скриншот | Читает код ошибки, ищет в Booble решение |
| **System Error** | «Выскочило окно, помоги» + скриншот | Понимает тип ошибки, выбирает токены с решением |
| **Скриншот кода** | «Почему не работает?» + скриншот | Ищет баг визуально (как в дебаге) |
| **Вирусные баннеры** | «Я просто зашёл почитать новости и...» + скриншот с баннерами | Юзер мнётся, отмазывается. Все понимают откуда реально баннер. Мини-арка: он стесняется, ты помогаешь, он благодарит шёпотом |

### Механика

1. Приходит сообщение с иконкой вложения
2. Кликаешь по иконке — картинка открывается в окне просмотра
3. В тексте запроса подсвечены ключевые слова
4. Кликаешь по словам — появляются токены с формулировками для описания/оценки
5. Собираешь ответ как обычно
6. Таймер тикает

## ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ

### Платформа
Unity, C#, UI Canvas.

### Файловая структура данных

### Структура сценария

```json
{
  "id": "s_001",
  "turns": [
    {
      "turn": 1,
      "keywords": ["kw_borscht", "kw_cook"],
      "cloud_ids": ["borscht", "beetroot", "beef", "cabbage", "broth", "boil", "noodles"],
      "correct":   ["borscht", "beef", "beetroot", "broth"],
      "trap":      ["noodles"],
      "required":  ["borscht", "broth"],
      "required_any": [["beef", "beetroot", "cabbage"]]
    },
    {
      "turn": 2,
      "keywords": ["kw_time"],
      "cloud_ids": ["boil", "two", "hours", "add", "noodles"],
      "correct":   ["boil", "two", "hours"],
      "trap":      ["noodles"],
      "required":  ["two", "hours"]
    }
  ]
}
```

- `cloud_ids` — все токены показанные в облаке для этого хода
- `correct` — правильные токены, дают очки
- `trap` — ловушки, снижают оценку
- `required` — обязательные, без них оценка падает
- `required_any` — хотя бы один из списка должен быть в ответе

### Локализация сценария

```json
{
  "s_001": {
    "turn_1": {
      "request": "Как приготовить борщ?",
      "kw_borscht": "борщ",
      "kw_cook": "приготовить",
      "reaction_good": "Спасибо, всё понятно! А сколько варить?",
      "reaction_bad":  "Это не рецепт борща..."
    },
    "turn_2": {
      "kw_time": "сколько",
      "reaction_good": "Отлично, попробую сегодня!",
      "reaction_bad":  "Вы уверены? Это слишком долго..."
    }
  }
}
```

### Инструмент редактора контента (HTML)

Весь контент игры (токены, сценарии, локализация) хранится в JSON-файлах. Для удобной работы с ними нужен **браузерный редактор** — локальный HTML-инструмент который открывается в браузере без установки.

**Что должен уметь редактор:**

- **Токены:** просматривать базу по категориям, добавлять новые токены, удалять, редактировать ID и переводы, добавлять новые языки
- **Сценарии:** создавать сценарии, добавлять ходы (turns), указывать ключевые слова, cloud_ids, correct/trap/required токены, редактировать тексты реакций
- **Локализация:** редактировать переводы для каждого языка отдельно
- **Поиск:** найти токен по ID или тексту, найти все сценарии где он используется
- **Валидация:** подсвечивать ошибки — если в сценарии указан несуществующий token_id, если обязательный токен не входит в cloud_ids и т.д.
- **Экспорт/импорт:** сохранять изменения обратно в JSON-файлы

**Почему HTML:** не требует установки, работает на любой машине, ИИ может генерировать готовые JSON-блоки которые сразу вставляются в редактор.

**Приоритет:** разработать до начала масштабного наполнения контентом.

## СИСТЕМА ДИАЛОГОВ

### Завершение диалога

Каждый ответ Дипака получает оценку (0-100%). От оценки зависит реакция юзера:

| Оценка | Реакция |
|--------|---------|
| 95%+ | Всегда доволен (награда за мастерство) |
| 80-94% | 90% доволен, 10% уточняет |
| 50-79% | 40% доволен, 40% уточняет, 20% недоволен |
| <50% | 30% жалоба, 70% недоволен |

Максимум попыток на одну тему: 3-5. После лимита — жалоба или юзер уходит.

### Модификаторы

**Типаж юзера:**
- Karen: порог +15%, шанс "angry" +20%
- Boomer Bob: порог -10%, шанс "satisfied" +15%

**Версия ИИ:**
- v1-v2: юзеры терпимее (+10% к оценке)
- v4-v5: юзеры требовательнее (-10% к оценке)

**Накопительное недовольство:**
Если юзер был недоволен предыдущим ответом: "satisfied" -20%, "angry" +20%.
